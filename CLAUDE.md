## Логика шахматки

**Строки** = уникальные номера этажей, отфильтрованные по корпусам из текущего фильтра, по убыванию.

**Столбцы** = все корпуса × подъезды × все работы из справочника.
Группировка заголовков: **Корпус › Подъезд › Захватка › Система › Локация › Работа** (6 уровней).
Работы повторяются для каждого подъезда корпуса. Подъезды берутся из «Доп признак» (Факт, col I).
Отображаемое имя работы = столбец I «Название для шахматки» (справочника).
Заголовки работ — вертикальный текст (`writing-mode: vertical-lr`), высота 140px.

**Ячейка** = пересечение (этаж, корпус, работа).
- Белая ☐ = не выполнена
- Зелёная ☑ = статус «СМР окончены» или PCT = true/TRUE/100
- Серая = нет строки в реестре этажей для этой комбинации

**Панель тегов** (`#selbar`, `updateSelTags`, вызывается из `render()` и `updateAddbar()`): в режиме создания/правки — оранжевые теги работ из выделенных ячеек («Система · Работа ×N»), клик по тегу убирает работу из выделения (`removeWorkFromSelection`); при выбранном в панели чек-листе (`SEL_CHK`, без режима выделения) — синие теги работ этого чек-листа (`chkview`, только просмотр).

**Подсветка шапки работ и этажей** (`buildHeaders`/`buildBody`): в режиме выделения (создание/правка чек-листа) работы с выделенными ячейками — оранжевые в шапке (`hl-sel`), этажи — оранжевые слева (`rh-sel`); живое обновление кликом через `refreshWorkHl` (`th[data-wk="workId|corpus"]`) и `refreshFloorHl` (`td.rh[data-floor]`). При выбранном в панели чек-листе (`SEL_CHK`) его работы в шапке — синие (`hl-chk`), этажи — голубые (`rh-hl`). Выделенные ячейки в режиме добавления/правки — сплошная оранжевая заливка (`body.add-mode td.cell.c-sel`), а не только рамка.

**Клик по ячейке — приоритет режимов** (обработчик на `#board`):
1. **`ADD_MODE`** (кнопка «+ Чек-лист») → выделение ячейки (`toggleSelect`);
2. иначе **`CHECK_MODE`** (чекбокс «📋 Чек листы») → открыть карточку работы (`openWorkCard`);
3. иначе — **правка готовности** (`cellClick`):
   - Белая → оптимистично зелёная, фоном пишет в «Факт»: Статус=«СМР окончены», Дата=сегодня, PCT=true;
   - Зелёная → подтверждение «Снять отметку?» → очищает F–H;
   - при ошибке сервера — откат UI.

**Авторизация:** правка (готовность, добавление/статус чек-листа) требует входа — без него клик открывает модал пароля. После ввода `adminCC` флаг в `sessionStorage` (`cc_admin`) до закрытия вкладки. Кнопка «Войти» — вход заранее. Гейт клиентский: сервер пароль при записи не проверяет. **Просмотр (в т.ч. чек-листы и карточка) открыт всем без входа.**

Топбар: «↺ Обновить», «Войти», чекбокс «📋 Чек листы», «+ Чек-лист», «📊 Аналитика физика», «📊 Аналитика чек-листы». Кнопки зума и «Что нового» удалены (модалка «Что нового» и её функции остались в коде, но не вызываются).

**Аналитика** (`#an-overlay`, `openAnalytics(mode)`, кнопки прижаты вправо): одна сводная таблица — строки-системы раскрываются в корпуса (`data-tgl`/`data-grp`), **столбцы — месяцы** (по возрастанию, «Без даты» в конце) + итоговые. Режим `fact` (`anFactPivot`/`renderFactPivot`): в ячейках — готовых позиций за месяц (по дате готовности), итоги Готово/Всего/%; режим `chk` (`anChkPivot`/`renderChkPivot`): уникальных чек-листов за месяц (по дате чек-листа), итог Всего; требует `CHECKS_LOADED`. Внизу строка «Всего». Фильтры шахматки не учитываются — всегда весь объект. Окно 820px, таблица скроллится по горизонтали при большом числе месяцев.

## Фильтры
- **Корпус** — chips (К1, К2…); фильтрует также список этажей в строках
- **Группа** — select по полю «Группировка» (справочник col G)
- **Захватка** — select
- **Система** — select
- **Локация** — select
- **Работа** — select по «Название для шахматки»
- **Чек-лист №** — текстовое поле (`#fchknum`). Без браузерных подсказок: `autocomplete="off"` одного атрибута Chrome игнорирует (известная особенность — подсказывает по имени/id поля вне зависимости от него), поэтому поле **без атрибута `name`** в разметке, а при загрузке страницы JS присваивает случайное имя (`fchknum.name = 'q' + random()`), чтобы браузеру не за что было зацепиться историей. Оставляет только работы (столбцы), у которых есть чек-лист с этим номером (`worksByChecklistNumber` сверяет внутренний № и номер акта внешних; совпадение **частичное**, без учёта регистра — «7» найдёт «7-С4.СБ3-АПС»). Работает после фоновой загрузки `checkByCell`.

**Панель тегов `#selbar` размещена под статус-баром** (не после топбара — там её перекрывало). Кнопки 📊 прижаты вправо: `margin-left:auto` только у первой кнопки, у `.sync` авто-отступ убран (два auto-отступа делили свободное место пополам, и кнопки висели по центру).

**Раскладка страницы — flex-колонка на всю высоту** (`html,body{height:100%}`, `body{display:flex;flex-direction:column}`), а не `.board-wrap{max-height:calc(100vh-130px)}` с зашитой цифрой. Топбар/фильтры/статсбар/`#selbar` — `flex-shrink:0`, `.board-wrap{flex:1 1 auto;min-height:0;overflow:auto}` тянется на весь остаток. Так шапка любой реальной высоты (появление `#selbar` добавляет строку) не обрезает доску сверху — раньше жёсткая `calc()` не учитывала лишнюю строку тегов, и верхние строки корпусов уезжали за экран. Топбар больше не `position:sticky` — он и так не скроллится, скроллится только `.board-wrap`.

## Внутренние чек-листы (загрузка через сайт)

Пользователь загружает чек-листы прямо из шахматки:
1. Кнопка **«+ Чек-лист»** в топбаре (требует входа) → режим выделения (`ADD_MODE`, `body.add-mode`).
2. Клик по ячейкам выделяет их (`c-sel`, оранжевая рамка) — **только в пределах одного корпуса** (`ADD_CORPUS`).
3. Нижняя панель `#addbar` → «Загрузить чек-лист» → модалка `#up-overlay`: статус, файл (PDF/PNG ≤25 МБ), комментарий.
4. Файл читается как base64 и POST-ится на `addChecklist`.

**Бэкенд** (`saveInternalChecklist`): файл → папка **«Чек листы СС»** на Диске (`getOrCreateChecklistFolder`, ID в Script Properties `cc_chk_folder`), доступ «по ссылке». Затем по строке на каждую (работа+этаж) в лист **«Чек листы_внутренние»** (создаётся автоматически, если нет).

**Лист «Чек листы_внутренние»**: A ID(группа `IC-<ts>`) · B Дата · C Корпус · D Система (название) · E Этаж · F Статус · G Ссылка · H Файл · I Комментарий · J Номер · K Доп файлы · L Загрузил · M Изменено · N ID_работы (ключ привязки) · O Работа (название).
D и O — человекочитаемые названия из справочника (для чтения листа глазами); код привязывает чек-лист к ячейке по **N** (в старых строках до миграции ид лежал в D — чтение с запасным вариантом `r[13] || r[3]`). Разовая миграция выполнена 2026-07-14 (`?action=migrateInt`, идемпотентна — можно дёргать повторно). `ensureIntHeaders_()` дозаполняет только ПУСТЫЕ шапки — переименованные пользователем заголовки не перетирает.
Статус `Удалён` в столбце F = чек-лист «мягко» удалён через сайт: строки остаются в листе, но фронту не отдаются.
Столбец K «Доп файлы» — JSON-массив `[{n:имя, u:ссылка}]` догруженных фотографий (одинаковый во всех строках группы); фронт получает его как `extra` в записях `checkByCell` и показывает ссылки «📷 фото N» в панели и карточке.
Столбец L «Загрузил» — имя автора (хранится в localStorage `cc_user`, шлётся полем `user` во всех POST записи). Имя **обязательно** для любых изменений: в форме загрузки (`#up-user`) и панели правки (`#ab-user`) — видимое поле, предзаполненное сохранённым именем, без него сохранение блокируется (`takeNameFrom`); смена статуса / догрузка фото / удаление при пустом имени открывают модалку `#nm-overlay` (`openName`, паттерн колбэка как у пароля); после входа админа модалка предлагается сразу. Фронт получает имя как `by`: в карточке — «загрузил: Имя», в панели — подсказка при наведении.
Столбец M «Изменено» — последняя правка группы: `кто · дд.мм.гггг чч:мм · что` (статус/+фото/удалил), пишется `changeMark_()`. Шапки J–M гарантирует `ensureIntHeaders_()`.

**Именование файлов на Диске** (как у телеграм-бота): основной файл — `СС_К4_эт.2,3_№7_Есть замечания_10.12.2025.pdf` (`safeFileName_` вычищает запрещённые символы, расширение — `fileExt_` из имени или mime); догруженные фото — `СС_К4_эт.2,3_№7_фотоN.jpg` (N = порядковый номер в столбце K).

**Смена статуса** (`setChecklistStatus`): в карточке работы у внутренних чек-листов (`source:'internal'`) админу показывается `<select>` вместо бейджа; выбор меняет статус **для всей группы** (всех строк с этим `id`) — столбец F. Внешние чек-листы — read-only (зеркало acons-app, правка затёрлась бы при синхронизации).

`addInternalChecklists` дописывает эти записи в тот же `checkByCell` (ключ `workId\x00corpus\x00floor`, `source:'internal'`), поэтому счётчик и карточка показывают внешние и внутренние чек-листы вместе.

**Производительность:** `checkByCell` при массовом заполнении K разрастается (>2 МБ, матчинг ~1900 строк «Чек листы»). Поэтому чек-листы вынесены в отдельный эндпоинт `getChecklists` и грузятся **фоном** (`loadChecklists`, `CHECKS_LOADED`) — сетка (`getData`) показывается сразу, не дожидаясь их.

⚠️ **Drive-scope**: `DriveApp` требует авторизации Диска у аккаунта `kuzkin@acons.group`. После первого деплоя с этой фичей нужно один раз открыть редактор Apps Script, запустить любую функцию (напр. `getOrCreateChecklistFolder`) и принять запрос доступа — иначе загрузка файла вернёт ошибку авторизации (чтение/шахматка при этом работают).

## Связь работ с чек-листами (`checkByCell`)

> ⚠️ **Внешние чек-листы сейчас ОТКЛЮЧЕНЫ** флагом `INCLUDE_EXTERNAL = false` в `script.gs`.
> `getChecklists` отдаёт только внутренние. Логика ниже (код-мостик, `readChecklists`) сохранена
> и включается обратно установкой `INCLUDE_EXTERNAL = true`.

Имена работ в «Справочник работ» («Кабель») и в «Чек листы» («Разводка кабеля») **не совпадают**,
поэтому связь идёт через код-мостик:

1. **«Справочник работ» col K** «ИД чек лист» = код **«Чек листы иерархия» col D** (L2, напр. `БОТ-СЛБ-01-01`).
2. В иерархии код раскрывается в тройку имён: **E Раздел · F Подраздел · G Работа**.
3. Лист **«Чек листы»** матчится по той же тройке (E/F/G) **+ Корпус (C) + Этаж (D)**; ссылка = **O «Файлы (S3)»** (или P «Google Drive URL»).
4. Ячейка шахматки = (workId из Факта, корпус, этаж).

`getChecklists` отдаёт `checkByCell`: ключ `workId\x00corpus\x00floor` → массив записей.
- внешние: `{id, status, akt, date, link, source:'external'}`;
- внутренние: `{id, status, number, date, link, file, comment, source:'internal'}`;
- архивные (лист «Архив», `addArchiveChecklists`): `{id, status, akt, date, link, file, comment,
  by(подрядчик), source:'archive'}` — read-only в интерфейсе (бейдж «архив», статус не меняется),
  но админ может удалить (🗑 в панели → `deleteArchiveChecklist`, мягкое). `checkStats.archive` — число записей.

Имена нормализуются (`trim` + lowercase + схлопывание пробелов), этаж — через `floorNorm` (запятая→точка, parseFloat).

`checkStats` в ответе — диагностика: сколько кодов в иерархии, сколько работ с кодом, сколько кодов не найдено,
сколько строк «Чек листы» сматчилось, топ несовпавших троек (`unmatchedTop`). Используется для проверки словаря.

### Интерфейс чек-листов
- Чекбокс **«📋 Чек листы»** в топбаре (`#chk-mode`, `CHECK_MODE`). При включении:
  - справа появляется **панель чек-листов** (`#chk-panel`): список чек-листов, попадающих
    в текущий фильтр (группировка по `id`; отображаются № / акт, статус, корпус, этажи, дата).
    Клик по чек-листу — подсветка его ячеек на шахматке (`c-chk-hl`, синяя рамка) и номеров
    этажей слева (`rh-hl`), клик по подсвеченной ячейке автоскроллит доску к первой из них;
    повторный клик снимает подсветку (`SEL_CHK`). Нижняя строка карточки (`cp-actions`) у
    внутренних чек-листов: **статус** (админу — селект `statusSelect`/`changeChecklistStatus`,
    на всю группу; остальным — бейдж), кнопка **📷 N** — открывает **модалку файлов**
    (`#ph-overlay`: первым идёт основной файл чек-листа «📋», затем догруженные фото; сетка
    миниатюр через `drive.google.com/thumbnail?id=` — работает и для PDF, при недоступной
    миниатюре показывается значок 📄/🖼; внизу кнопка «＋ Добавить» → выбор файлов
    `#cp-photo-inp`, multiple, только админ; файлы шлются последовательно по одному POST
    `addChecklistFile`), кнопка **✏️ редактировать состав** — включает тот же режим
    выделения ячеек, что и «+ Чек-лист» (`EDIT_CHK`): текущие ячейки чек-листа уже отмечены,
    кликами добавляем/убираем (корпус зафиксирован); в нижней панели появляются поля
    **№ / дата / комментарий** (`#addbar-edit`, предзаполнены текущими значениями), кнопка
    становится «Сохранить» (`addbarPrimary` → `saveEditCells`) → POST `editChecklistCells` +
    локальное обновление (`updateLocalChecklistMeta`, `applyLocalCells`); файл/статус/фото
    не меняются; и кнопка **🗑 удалить**
    (с подтверждением) → POST `deleteChecklist` (мягкое удаление, см. эндпоинты).
    Под строкой управления показывается **комментарий** чек-листа («💬 …», если есть).
    Догруженные фото также видны в карточке работы ссылками «📷 фото N».
    Панель открывается и при входе в режим «+ Чек-лист». Доска сдвигается влево
    (`body.chk-open .board-wrap { margin-right }`), позиция верха панели — под статус-баром
    (`positionChkPanel`, пересчёт на resize).
  - в ячейках сохраняется цвет готовности (зелёная/белая), но вместо ☑/☐ выводится **количество чек-листов** (`c-count`); пусто, если 0;
  - **окантовка ячейки по статусу** (`checkStatusClass`): красная = «Есть замечания» (`c-st-red`), жёлтая = «Замечания устранены» (`c-st-yellow`), тёмно-зелёная = «Принято» (`c-st-green`). Приоритет при нескольких: красный > жёлтый > зелёный;
  - клик по ячейке открывает **карточку работы** (`#card-overlay`) вместо переключения статуса.
- Карточка: имя работы, система/захватка/локация/расположение, список чек-листов. По каждому: статус, **акт (внешние) / № (внутренние)**, имя файла, дата, кнопка **«Открыть ↗»** (ссылка). У внутренних админу вместо бейджа — `<select>` для смены статуса (`statusSelect` → `changeChecklistStatus` → `setChecklistStatus`, на всю группу).
- Ключ поиска чек-листов на фронте: `workId\x00corpus\x00floorNum` (совпадает с `checkByCell`). Подъезд в ключе не участвует — чек-листы его не различают, поэтому одинаковые ячейки разных подъездов показывают один и тот же набор.

## Известные особенности
- **Прокси**: системный прокси `127.0.0.1:10808` блокирует `clasp` — всегда сбрасывать переменные окружения перед push/deploy
- **onclick в innerHTML**: нельзя использовать `JSON.stringify()` в атрибутах onclick — двойные кавычки ломают HTML. Вместо этого используются `data-*` атрибуты + event delegation на `#board`
- **LockService**: убран из `saveCellFact` — каждая ячейка пишет в уникальную строку, конкурентных конфликтов нет; замок создавал очередь и таймауты при быстрых кликах
- **Оптимистичный UI**: ячейка обновляется мгновенно при клике, запрос к GAS идёт фоном; при ошибке — откат
- **GitHub Pages / Jekyll**: нужен `.nojekyll`; легаси-сборщик иногда виснет — пинать через `gh api --method POST .../pages/builds` (см. раздел «Деплой»)
- **POST к GAS**: слать с `text/plain` body (иначе CORS-preflight, который GAS не обрабатывает)
- **Drive-scope**: `DriveApp` (загрузка файлов) — разовая авторизация Диска у `kuzkin@acons.group` через редактор Apps Script (см. раздел про внутренние чек-листы)
- **Транзиентный HTML вместо JSON**: GAS exec иногда отдаёт HTML-страницу (редирект/ошибка/долгий ответ) → `JSON.parse` падает («Unexpected token `<`»). GET-запросы идут через **`fetchJson`** с автоповтором (до 3 раз, пауза 1.5с). `getData`/`getChecklists` отвечают медленно (~10–20с — латентность/холодный старт Google и открытие большой таблицы, не объём данных)
